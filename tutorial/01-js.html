0. 三个先建立的心理准备

1. 一切皆"值"，函数也是值

Python 里函数是一等公民 —— JS 里更是。函数可以被赋值给变量、当参数传、当返回值返回。这个项目里到处都是这种写法。

2. 异步是显式的

读文件、发请求都返回 Promise。不加 await 你就拿到一个"还没好的东西"。Python 也是这套，但要更小心 —— 忘了 await 不会报错，只会静默出错。

3. 没有类型，但有 undefined

Python 的 None 在 JS 里有两个亲戚：null 和 undefined。代码里大量用 ?. 和 ?? 来对付它们。

1. 变量声明：const 和 let

Python 直接 x = 1。JS 要声明，而且声明方式有含义：

JS含义Python 类比
const x = 1不能再指向别的值（但对象内容能改）没有完全对应的，约等于"约定不重新赋值"
let x = 1可以重新赋值x = 1
var老写法，本项目不用—
关键区别：const ≠ 不可变

const 只锁住"这个变量名指向谁"，不锁对象内部。const a = [] 之后 a.push(1) 完全合法。这个项目里到处都是 const state = {...}，然后拼命改 state.xxx。

src/host/service.js:60
const state = {
  settings: { ...DEFAULT_SETTINGS },
  discovered: null,
  game: null,
  catalog: new Map(),
  mods: [],
  duplicates: [],
  scannedAt: null,
  config: null,
  configMtime: 0,
  ready: null,
}

后面代码会写 state.mods = r.mods —— 合法，因为改的是对象的属性，不是 state 这个变量本身。

2. 箭头函数 —— 本项目 90% 的函数都是这种

Python 的 lambda 只能写一个表达式，JS 的箭头函数可以写完整的函数体。这是你最先要适应的东西。

单表达式（像 lambda）

const double = (x) => x * 2

Python: double = lambda x: x * 2

带函数体（像 def）

const f = (a, b) => {
  const s = a + b
  return s
}

Python: def f(a, b): ...

看真实代码：

src/host/xml.js:8
export const pid = (s) => String(s || '').trim().toLowerCase()
逐段拆解这一行（点开）

这是一个"单表达式箭头函数"，等价于：

export function pid(s) {
  return String(s || '').trim().toLowerCase()
}

再逐步看：

  • s || '' → 如果 s 是 undefined / null / '' / 0，用 '' 代替。（这是 JS 的"假值"机制，见第 6 节）
  • String(...) → 转字符串，str() 一样
  • .trim() → 去掉首尾空格
  • .toLowerCase() → 转小写

Python 版本：def pid(s): return str(s or "").strip().lower() —— 几乎逐字对应。

只有一个参数时可以省括号

src/host/service.js:129（节选）
const activeKeys = () => (state.config?.activeMods || []).map(pid)

() => 是零参数（像 Python 的 lambda: ...）。.map(pid) 是把 pid 这个函数直接传进去 —— 相当于 Python 的 map(pid, ...)，稍后第 8 节讲。

最容易踩的坑：函数体用 {} 就必须 return

// ✗ 错：返回 undefined！因为 {} 被当成了函数体
const f = (x) => { x * 2 }

// ✓ 对
const f = (x) => { return x * 2 }
const f = (x) => x * 2        // 没有 {} 才是隐式返回

// ✓ 想返回一个对象，必须加括号
const f = (x) => ({ ok: x })   // 不加括号会被当成函数体

仓库里到处是这种"返回一个对象"的箭头函数：

index.js:116
const textOut = (fn) => ({
  schema: { type: 'object', additionalProperties: true },
  render: (args, value) => [{ type: 'text', text: fn(value) }],
})

这里 textOut 是个高阶函数：你给它一个"格式化函数" fn，它返回一个描述"工具输出格式"的对象。Python 里你会这么写：

def text_out(fn):
    return {
        "schema": {"type": "object"},
        "render": lambda args, value: [{"type": "text", "text": fn(value)}],
    }

3. ?. 和 ?? —— 你会看到几百次

这两个是 JS 的救命符，Python 里没有直接对应物。它们专门对付 null / undefined。

写法含义Python 类比
a?.b如果 a 是 null/undefined，整个表达式就是 undefined（不报错）；否则取 a.b没有。a.b if a else None 但只在 a 为 None 时短路
a ?? b如果 a 是 null/undefined，用 b；否则用 aa if a is not None else b
a \|\| b如果 a 是"假值"（null、undefined、0、''、false、NaN），用 ba or b
?? 和 || 的区别要记牢

0 || 5 得到 5（因为 0 是假值）；0 ?? 5 得到 0（因为 0 不是 null）。数字类型的默认值必须用 ??，否则用户设的 0 会被吞掉。

看这个真实例子 —— 用户把 waitMs 设成 0 是有意义的（"立刻强杀"），所以这里必须用 ??：

args.waitMs != null ? { waitMs: args.waitMs } : {}

真实代码里两个连用：

src/host/sorter.js:309
const nameOf = (k) => catalog.get(k)?.name || ruleStore?.steamByPid(k)?.name || k

翻译成中文：

  1. 从 catalog 里找这个 key，找到了就取 .name，找不到（catalog.get(k) 返回 undefined）就整体是 undefined
  2. 如果没有名字，试试从 steam 数据库里查
  3. 还是没有，就返回这个 key 本身（保证一定有值）

Python 版本会很难看（需要 try/except 或层层 if），这就是 JS 的 ?. 的价值：一条链上任何一环缺失都不会崩。

4. 解构赋值 —— 从对象/数组里"拆"出变量

Python 有 a, b = b, a。JS 把它扩展到了对象，而且用得像呼吸一样频繁。

数组解构

const [a, b] = [1, 2]           // a=1, b=2   （≈ Python: a, b = 1, 2）
const [x, ...rest] = [1, 2, 3]  // x=1, rest=[2,3]  （≈ Python: x, *rest = ...）

真实用法：

src/host/sorter.js:270
const keys = [...new Set(activeKeys.map(pid))]
const { edges, tiers } = buildGraph(keys, catalog, ruleStore)

第二行是对象解构：buildGraph 返回 { edges, tiers }，这里一次性拆成两个变量。Python 只能写：

g = build_graph(...)
edges, tiers = g["edges"], g["tiers"]

带默认值的解构 —— 这个项目超爱用

src/host/sorter.js:268
export function sortLoadOrder(activeKeys, catalog, ruleStore, { tieBreak = 'name' } = {}) {

这个签名要仔细看，它包含两个技巧：

第 4 个参数在签名里就解构成 { tieBreak } —— 调用者传的是一个对象 { tieBreak: 'rimsort' }
tieBreak = 'name'对象里没有这个属性时用默认值 'name'
= {}整个对象参数本身如果没传（undefined），用空对象兜底。少了这个，调用 sortLoadOrder(a,b,c) 会直接崩

Python 的等价写法要啰嗦得多：

def sort_load_order(active_keys, catalog, rule_store, opts=None):
    opts = opts or {}
    tie_break = opts.get("tieBreak", "name")

5. 展开运算符 ... —— 复制、合并、传参

一个符号三种用途，都很常见。

① 复制 / 合并对象（最常用来做"不可变更新"）

src/host/service.js:333
state.config = { ...state.config, activeMods: next }

意思是：造一个新对象，先塞进 state.config 的所有字段，再用 activeMods: next 覆盖其中一项。Python 版本：

state["config"] = {**state["config"], "activeMods": next}
为什么非要用新对象？

因为前端 React 判断"数据变没变"是靠引用比较（old === new）。原地改 state.config.activeMods = next 引用不变，React 就不知道要重画界面。所以整份代码里都用 {...old, key: value} 来更新。这就是"不可变数据"习惯。

② 复制 / 合并数组

const copy = [...arr]                    // 浅拷贝，≈ arr[:] 或 list(arr)
const merged = [...a, ...b]              // ≈ a + b
const uniq = [...new Set(arr)]           // 去重，≈ list(dict.fromkeys(arr))

第 4 页会看到这个：

src/host/sorter.js:275
const edgeList = [...edges.values()]

edges 是 Map，.values() 返回一个迭代器。用 [...] 把它"摊开"成数组 —— 完全等价于 Python 的 list(edges.values())。

③ 把数组当参数列表传进去

console.log(...arr)              // ≈ print(*arr)
next.splice(position, 0, ...add) // 把 add 里的每个元素都插进去

6. 真值 / 假值 —— Python 直觉基本能迁移

JS 里被视为"假"的值：false、0、-0、0n、""、null、undefined、NaN。其他一切都是真。

两个 Python 程序员必踩的坑
表达式JS 结果Python 结果
[] ? 'a' : 'b''a'（空数组是真！）'b'（空列表是假）
{} ? 'a' : 'b''a'（空对象也是真）'b'

所以判断数组空不空必须写 arr.length === 0，判断对象空不空要用 Object.keys(obj).length === 0。

真实代码里就遵守了这个规则：

index.js:147 附近（节选）
s.mods.filter((m) => m.source === 'workshop').length

而不是 if (s.mods)。

常用简写

a || b          // a 假就用 b          ≈ a or b
a && b          // a 假就用 a，否则 b   ≈ a and b
!a              // 取反                ≈ not a
!!a             // 转成真正的布尔值      ≈ bool(a)
a > 0 ? x : y   // 三元                ≈ x if a > 0 else y

三元表达式在 JSX 里用得极多（第 7 页）：

src/client/app.jsx:202
<button onClick={() => startGame(false)}>▶ 启动</button>

而 && 常用来"条件渲染"，等价于 Python 的 if 保护：

src/host/service.js:329（节选，改写排版）
lines.push(
  v.cloned.length && `Cloned from git (${v.cloned.length}): ...`
)

当 v.cloned.length 是 0（假值）时，整个表达式是 0；后面 .filter(Boolean) 会把它滤掉。这是"只在有内容时才加这一行"的惯用法。

7. 相等：=== 不是 ==

本项目只用 === 和 !==，从不使用 ==。照做就行。

写法行为
===严格相等：类型不同就不等。1 === '1' → false
==会做类型转换，坑很多。1 == '1' → true。别用。
但对象和数组永远不"相等"

[1,2] === [1,2] 是 false！因为比的是引用（是不是同一块内存），不是内容。想比内容要手动比较，或者像这个项目一样：

const dirty = draft !== null && JSON.stringify(draft) !== JSON.stringify(snap?.active || [])

（src/client/store.js:40）用 JSON 字符串来比数组内容。简单粗暴但有效。

.sort() 的两个坑

坑一：默认按字符串排

[10, 9, 1].sort() 得到 [1, 10, 9]！必须传比较函数：.sort((a,b) => a - b)。

坑二：原地修改

arr.sort() 会改掉 arr 本身（Python 也一样），所以本项目常常先复制：

return [...keys].sort((a, b) => collator.compare(...))

（src/host/sorter.js:174）

比较函数的约定：返回负数 = a 在前，正数 = b 在前，0 = 相等。这正是 Python key= 背后做的事，只是 JS 让你手写。

src/host/sorter.js:174
return [...keys].sort((a, b) => collator.compare(sortName(a, catalog), sortName(b, catalog)) || collator.compare(a, b))

这里的 || 用得妙：如果第一个比较返回 0（名字一样），就退而比较 key。典型的"多级排序"。

这个项目大量使用 Map 而不是普通对象，因为 mod 的 key 可能包含点号、可能有特殊字符，用 Map 更安全也更快。

10. 模块：export / import

注意 package.json 里有一行 "type": "module" —— 这意味着这个项目用的是 ESM（和 Python 的模块最接近），不是老的 CommonJS（require）。

命名导出（可以有多个）

export function pid(s) {...}
export const CORE_ID = '...'
export { scanMods, CORE_ID }

默认导出（只能有一个）

export default plugin
src/host/sorter.js:20-21
import { pid } from './xml.js'
import { CORE_ID, KNOWN_EXPANSIONS } from './scan.js'
三个和 Python 不同的地方
  1. 路径必须写 .js 后缀。Python 是 from .xml import pid，JS 必须 from './xml.js'。
  2. 相对路径必须以 ./ 或 ../ 开头。from 'xml.js' 会被当成 npm 包去找。
  3. import 会被"提升"到文件最顶部执行，不能像 Python 那样写在函数里按需导入（虽然有动态 import()，本项目不用）。

11. 异步：async / await / Promise

这块和 Python 的 asyncio 概念一样，但语法细节要记。

思路对比
# Python
async def rescan():
    text = await read_file(path)
    return parse(text)

// JavaScript
const rescan = async () => {
  const text = await readFile(path, 'utf8')
  return parse(text)
}

真实代码：

src/host/service.js:124-137
const rescan = async () => {
  state.discovered = await discoverPaths()
  const p = effectivePaths()
  state.game = await readGameVersion(p.gameDir)
  const r = await scanMods({ ...p, major: state.game?.major, extraDirs: p.extraModDirs })
  state.catalog = r.byId
  state.mods = r.mods
  state.duplicates = r.duplicates
  state.scannedAt = Date.now()
  await loadConfig()
  ...
  return { count: r.mods.length }
}

几乎逐行对应 Python 的 async def。

并发：Promise.all ≈ asyncio.gather

src/host/scan.js:116-121
await Promise.all(
  names.map(async (name) => {
    const m = await scanOne(path.join(base, name), source, major, name)
    if (m) found.push(m)
  }),
)

同时扫描所有 mod 文件夹（每个都要读 XML），比一个个 await 快得多。Promise.all 会等所有任务全部完成。

和 Python 的一个重要区别

JS 是单线程的。没有"几个函数真并行跑"，只是"等 I/O 的时候切换到别的任务"。所以这段代码里 found.push(m) 不需要加锁 —— 永远不会有两段代码同时执行。这反而比 Python 多线程简单。

.then() 链 —— 另一种写法

index.js:31-34
service.init().then(
  () => log(`ready: ${service.state.mods.length} mods`),
  (e) => log('init failed: ' + (e && e.message)),
)

.then(成功回调, 失败回调) 是 await 还没出现时的写法。它不会阻塞 —— 这行执行完立刻继续往下走，初始化在后台跑。这就是为什么 index.js 能先启动服务、后注册路由。

五个函数长得像 async 但不是：注意分辨

写法是什么
async () => {...}异步函数，返回 Promise
() => promise返回 Promise 的普通函数（如 const init = () => (state.ready ||= ...)）
() => api('snapshot')同上，api 内部是 async
await service.dispatch(...)等它完成
忘了 await拿到一个 Promise 对象而不是结果 —— 最常见的 bug

正则字面量

/^\d+$/.test(t)              // ≈ bool(re.fullmatch(r'\d+', t))
text.matchAll(/"path"\s+"([^"]+)"/g)  // ≈ re.finditer(r'...', text)

数字与时间

Date.now()                              // 毫秒时间戳，≈ int(time.time() * 1000)
new Date().toISOString()                // ISO 字符串
(ms / 1048576).toFixed(1)               // 保留一位小数，≈ round(x, 1)（但 toFixed 返回字符串）
Math.max(0, Math.min(len, n))           // ≈ max(0, min(len, n))
Math.floor(x)                           // ≈ x // 1（注意不是 int(x)，负数不一样）
Number(x) || 0                          // ≈ int(x or 0)

JSON

JSON.stringify(obj)         // → 字符串   ≈ json.dumps
JSON.stringify(obj, null, 2) // 带缩进
JSON.parse(str)             // → 对象     ≈ json.loads
一个 hack，但在这项目里是有意的设计

index.js:123 有这一行：

return JSON.parse(JSON.stringify({ ok: true, ...(await ...) }))

先把结果转成 JSON 字符串再转回来。为什么？因为要丢掉 undefined、Map、Set、函数这类东西，只留下干净的 JSON 数据（AI 工具的输出必须能被序列化）。Python 里你会写 json.loads(json.dumps(x, default=str)) 做同样的事。

try {
  ...
} catch {
  ...
} finally {
  ...       // 可选，≈ finally
}

注意 catch 后面可以不带括号（不关心异常对象）。本项目大量使用"空 catch"来静默忽略错误：

switch (args.action) {
  case 'list': return run('lists', {})

16. 现在试一下：读懂这 4 行

这是 src/host/service.js 里真实的一行（第 93 行）。用上面的知识拆解它：

src/host/service.js:92-96
const mergeDb = (d) => {
  const out = JSON.parse(JSON.stringify(DEFAULT_DB_CONFIG))
  for (const k of DB_KEYS) if (d && d[k] && typeof d[k] === 'object') out[k] = { ...out[k], ...d[k] }
  return out
}
点开看逐行解释
  1. const mergeDb = (d) => { ... }
    定义函数 mergeDb，参数 d。返回函数体最后 return 的东西。
  2. JSON.parse(JSON.stringify(DEFAULT_DB_CONFIG))
    深拷贝。JSON.stringify 转成文本，JSON.parse 再转回对象 —— 这样新对象和原来的完全没关系，改动不会影响 DEFAULT_DB_CONFIG 常量。Python: copy.deepcopy(DEFAULT_DB_CONFIG)
  3. for (const k of DB_KEYS)
    遍历键名数组。
  4. if (d && d[k] && typeof d[k] === 'object')
    三道检查：d 存在、d[k] 存在、d[k] 确实是对象。typeof 是 JS 的 type()。
  5. out[k] = { ...out[k], ...d[k] }
    用用户配置里的值覆盖默认值，但保留默认值里用户没提到的字段。这是"合并配置"的标准写法。
  6. return out
    返回合并后的新对象。

Python 等价物：

def merge_db(d):
    out = copy.deepcopy(DEFAULT_DB_CONFIG)
    for k in DB_KEYS:
        if d and d.get(k) and isinstance(d[k], dict):
            out[k] = {**out[k], **d[k]}
    return out

看，几乎一模一样。这就是为什么你会 Python 就能读这个项目。
